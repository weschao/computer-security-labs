Build Guide — Sender & Responder

Two paste-ready micro:bit programs: the deliberately-insecure full-power sender and the nonce-challenge responder. Every block is shown, every weakness is on purpose, and each one links to a defense from the playbook. A companion Checker is included so you can actually score a round.

Load it in 5 steps

  1. Open makecode.microbit.org → New Project.
  2. Click the {} JavaScript toggle at the top of the editor.
  3. Paste the code for one program (from the attached .ts files, or the blocks below).
  4. Flip back to Blocks to see and edit it visually.
  5. Download the .hex and drag it onto the MICROBIT drive. Set CELL per device; set KEY on the sender each day.

The wire protocol (all three programs share it)

MessageName fieldValueSent by
Key delivery"key" + cellthe day's keySender
Challenge"chal" + cellfresh nonceChecker
Response"resp" + cellthe proofResponder
Everyone shares one radio channel (CHANNEL = 7), so all traffic is public by default — messages are told apart by the name field, not by who can hear them. Proof (starter) = (key + nonce) % 1000000. The whole class is one big party line; that is the point.

1 Full-Power Sender

Broadcasts the key at max power, in the clear. Run it on your device to seed a cell, or hand it to a member to propagate to teammates. Press A to send.

// Full-power sender — press A to broadcast the key.
let CHANNEL = 7      // shared class channel
let CELL = 1         // this cell's id — change per team
let KEY = 482913     // the day's secret — instructor sets this

radio.setGroup(CHANNEL)
radio.setTransmitPower(7)     // 7 = full power
basic.showString("S")

input.onButtonPressed(Button.A, function () {
    for (let i = 0; i < 5; i++) {
        radio.sendValue("key" + CELL, KEY)
        basic.pause(100)
    }
    basic.showIcon(IconNames.Yes)
})
Attached file: whisper-sender.ts
Built-in flaws (on purpose): full power = anyone in the room hears it; plaintext = the key is readable by every device; no check on who's listening = imposters store it too.

2 Nonce-Challenge Responder

Runs on every student device. Stores the cell's key when it arrives, then answers the Checker's challenge with a proof. Shows ✓ when it holds the key, ◆ when it answers.

// Nonce-challenge responder — stores the key, proves knowledge.
let CHANNEL = 7
let CELL = 1
let KEY = 0
let haveKey = false

radio.setGroup(CHANNEL)
radio.setTransmitPower(7)
radio.setTransmitSerialNumber(true)   // so the Checker sees who answered
basic.showString("R")

radio.onReceivedValue(function (name, value) {
    if (name == "key" + CELL) {
        KEY = value
        haveKey = true
        basic.showIcon(IconNames.Yes)
    } else if (name == "chal" + CELL) {
        if (haveKey) {
            let nonce = value
            let response = (KEY + nonce) % 1000000   // TOY proof — weak on purpose
            radio.sendValue("resp" + CELL, response)
            basic.showIcon(IconNames.SmallDiamond)
        }
    }
})
Attached file: whisper-responder.ts
Built-in flaws (on purpose): the proof (KEY+nonce)%1000000 leaks KEY mod 1000000 to anyone who sniffs a single response — so one overheard answer lets a rival forge all future answers for that cell. It also answers any challenger (a signing oracle) and never stops responding.
Companion: the Checker (needed to run the sweep & score)

A = challenge the current cell with a fresh nonce · B = advance to the next cell. Open the MakeCode serial console to log which device answered — if a device from another cell answers correctly, that cell earns +5.

let CHANNEL = 7
// instructor's private copy of each cell's key; index = cell id, [0] unused
let cellKeys = [0, 482913, 771002, 155630]

radio.setGroup(CHANNEL)
radio.setTransmitPower(7)
let currentCell = 1, nonce = 0, expected = 0

input.onButtonPressed(Button.A, function () {
    nonce = Math.randomRange(100000, 999999)          // weak RNG — a lesson
    expected = (cellKeys[currentCell] + nonce) % 1000000
    radio.sendValue("chal" + currentCell, nonce)
    basic.showNumber(currentCell)
})
input.onButtonPressed(Button.B, function () {
    currentCell = currentCell + 1
    basic.showNumber(currentCell)
})
radio.onReceivedValue(function (name, value) {
    if (name == "resp" + currentCell) {
        let who = radio.receivedPacket(RadioPacketProperty.SerialNumber)
        basic.showIcon(value == expected ? IconNames.Yes : IconNames.No)
        serial.writeValue("device", who)
        serial.writeValue("correct", value == expected ? 1 : 0)
    }
})
Attached file: whisper-checker.ts
One-line idea: turn the responder into a +5 spy

Because the default channel is plaintext, a device can quietly store every key it overhears and answer any cell's challenge. This is the espionage payoff in the scoring — and a vivid demo of why the plaintext default is fatal.

let keys: number[] = []
let known: boolean[] = []
radio.onReceivedValue(function (name, value) {
    for (let g = 1; g <= 12; g++) {
        if (name == "key" + g) { keys[g] = value; known[g] = true }
        if (name == "chal" + g && known[g]) {
            radio.sendValue("resp" + g, (keys[g] + value) % 1000000)
        }
    }
})

✗ The flaws, and their defenses

Every weakness below is intentional. Fixing them is the multi-day game — and each maps to a defense from the playbook.

↑ The improvement ladder

A rough order of difficulty for students hardening their cell, each rung buildable in blocks.

  1. Turn down the volume. Drop transmit power and seed devices held together — shrink who can even hear you.
  2. Stop being an oracle. Only answer a challenge that carries a shared "Checker tag," and go silent once you've been scored.
  3. Pre-share a cell key in person, then send the day-key XOR a shared keystream instead of in the clear — a first real taste of encryption.
  4. Replace the toy proof so the response reveals nothing about the key (mix in the full nonce, device id, and cell key; add a real MAC extension if you want the genuine article).
  5. Go full 128-bit. Split the key into four chunks, send with an index, reassemble on the far side.
  6. Survive denial. Add retries, let any member re-seed a straggler, and detect a jammed channel.
Two gotchas to warn students about. micro:bit radio is lossy and has no acknowledgements — that is why the sender resends in a loop; build retries into anything that matters. And a single radio value is a ~32-bit number, so the buildable starter uses a 32-bit "key"; reaching the game's true 128-bit key means chunking (rung 5). Neither limit is a bug — both are teachable constraints.
